THE RUNTIME MAP

The three computers are genuinely different machines.

The page coordinates three instruction sets and two hard boundaries. “Local” does not mean everything runs in one JavaScript process.

Browser host     JavaScript + Wanix WebAssembly
       │          files and terminal bytes
       ▼
v86 guest        x86 Linux + Xtensa cross-compiler
       │          firmware.bin over Web Serial
       ▼
ESP8266 target   physical Xtensa microcontroller

What each machine contributes

  • The browser owns the page, Wanix namespace, generated source, artifact bytes and permission-gated USB connection.
  • v86 emulates an x86 PC capable of booting Alpine Linux. Inside it, ordinary command-line tools cross-compile for a completely different CPU.
  • The ESP8266 never runs Wanix or Linux. It receives the final flash image and boots that native firmware.
WANIX IDEA

Wanix gives the browser Unix-shaped ways to connect these components: mounted resources, paths, tasks and byte streams. After the static assets load, no build server sits between them.

DEEP DIVE · STEP 01

NAMESPACE COMPOSITION

The filesystem is assembled, not downloaded as one disk.

<wanix-namespace> creates a private root. Each child bind places a resource provider at a destination path, so unrelated implementations appear as one coherent tree.

<wanix-bind dst="." type="archive" src="wanix-linux.tgz">
<wanix-bind dst="workspace" src="#ramfs/new">
<wanix-bind dst="vm" src="#vm">
<wanix-vm export="ttyS0" mem="256M" term start>
  1. The Linux and ESP8266 toolchain archives populate normal-looking paths such as /opt/xtensa-lx106.
  2. #ramfs/new supplies a browser-memory filesystem at /workspace. JavaScript and the guest both see its files.
  3. #vm supplies the virtual-machine device. The v86 archive adds its driver, and <wanix-vm> boots the guest.
  4. The page waits for the guest’s #task path before enabling Build. Files appearing in the tree are the readiness signal.
WANIX IDEA

A path describes where a capability appears, not where its bytes physically live. HTTP archives, RAM and a device can all participate in the same namespace.

DEEP DIVE · STEP 02

SOURCE GENERATION

The controls generate a complete C++ translation unit.

Every input event calls firmwareSource(owner, cycleMs). The source panel is therefore a preview of the exact text that will become /workspace/main.cpp.

constexpr char kOwner[] = "Luke";
constexpr uint32_t kBlinkHalfPeriodMs = 500;

digitalWrite(LED_BUILTIN, LOW);  // LED on
delay(kBlinkHalfPeriodMs);
digitalWrite(LED_BUILTIN, HIGH); // LED off
  • The name is checked as UTF-8 and limited to 64 bytes, then encoded as a safe C++ string literal.
  • The selected full blink cycle is divided into equal ON and OFF delays. The D1 mini’s built-in LED is active-low, so LOW turns it on.
  • The Arduino core and SDK libraries are precompiled dependencies. This page still compiles the newly generated main.cpp, then links a new ELF and packages a new flash image.
WANIX IDEA

The UI is a source-code authoring tool. Personalization is not patched into a prebuilt firmware blob; it crosses the browser/guest boundary as an ordinary file.

DEEP DIVE · STEP 03

TERMINAL-DRIVEN BUILD

There is no special build RPC.

JavaScript treats the VM terminal as a duplex file. It writes a shell command to the same byte stream from which it reads compiler output.

const out = await root.openReadable(`${vm.term}/data`);
const input = await root.openWritable(`${vm.term}/data`);

BUILD_ID=build-… APP_SOURCE=/workspace/main.cpp \
  /bin/sh /workspace/build.sh
  1. The controller first writes workspace/main.cpp through the Wanix root API.
  2. The shell script compiles it with xtensa-lx106-elf-g++, links it with the packaged Arduino core and SDK, then runs wanix-elf2bin.
  3. Compiler scratch files live in a guest /tmp tmpfs; only useful outputs cross back into the shared workspace.
  4. A unique marker printed after the command carries its exit status. The page recognizes that marker in the terminal stream and then reads result.json.
WANIX IDEA

Automation and a person can drive the same real shell interface. The application composes familiar files and commands instead of requiring a custom guest API.

DEEP DIVE · STEP 04

ARTIFACT HANDOFF

The output crosses back through the namespace.

The guest copies its result files into a unique directory below /workspace/artifacts. Because that path is backed by Wanix RAM, browser JavaScript can immediately consume the same bytes.

await root.waitFor("workspace/artifacts/build-…/result.json");
const firmware = await root.readFile("…/firmware.bin");
const digest = await crypto.subtle.digest("SHA-256", firmware);
const url = URL.createObjectURL(new Blob([firmware]));
  • result.json carries build status, elapsed guest time and exact source, ELF and firmware byte counts.
  • readFile returns the binary firmware to JavaScript as bytes—not base64 and not an HTTP response.
  • WebCrypto computes the content identity. Blob URLs then expose those in-memory bytes to the download link and flashing component.
  • The ELF is the linked executable used to create the image; firmware.bin is the ESP8266 flash layout that starts at offset zero.
WANIX IDEA

The build result is not returned by a service call. Producer and consumer agree on paths, so a Linux process and a web component can exchange artifacts through files.

DEEP DIVE · STEP 05

A TERMINAL AS A FILE

The interactive shell and build controller share one endpoint.

<wanix-term> is an xterm UI attached to the VM’s terminal path. It does not imitate a shell; keyboard bytes go to Linux and terminal bytes come back.

const term = document.createElement("wanix-term");
term.setAttribute("for", "linux");
term.setAttribute("path", vm.term);
term.setAttribute("raw", "");
term.setAttribute("scrollback", "2000");
  1. The VM exports its serial console as a terminal device. Its data endpoint appears at #term/…/data.
  2. When you open the shell, the custom element opens that endpoint and renders the stream with xterm.
  3. The terminal has one owner at a time. Starting a build removes the interactive element before automation opens the stream; afterwards you can attach again.
  4. Detaching the UI does not stop v86. The guest, shell history and files continue to live in browser memory until the page reloads.
WANIX IDEA

A terminal is another namespaced resource. The same endpoint supports a polished web interface, scripted control and direct human inspection without inventing three different backends.
